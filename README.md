# HostPanel — панель управления хостингом для Linux

Репозиторий: https://github.com/enikov1/hostPanel

Бэкенд — чистый Python (только стандартная библиотека), фронтенд —
Vue 3 + Vite + vue-router (TypeScript), сборка лежит готовой в `panel/web`
(для установки node не нужен). Веб-интерфейс полностью на русском,
тёмная и светлая темы, реальные URL разделов (`/sites/`, `/databases/`…).

## Установка одной командой

На чистом Debian/Ubuntu (нужен только python3, он уже есть в системе):

```bash
curl -fsSL https://raw.githubusercontent.com/enikov1/hostPanel/main/install.sh -o install.sh && sudo bash install.sh
```

Установщик сам скачает репозиторий с GitHub, если рядом с ним нет `panel/`.
Альтернатива через git:

```bash
git clone https://github.com/enikov1/hostPanel.git && sudo bash hostPanel/install.sh
```

Что делает установщик: ставит стек служб (nginx, Apache как backend на :8081, PHP 8.3-FPM с модулями, MariaDB, certbot, Node.js + npm, Redis, Memcached, fail2ban), настраивает их, копирует пакет в `/opt/hostpanel/panel`, создаёт
systemd-службу `hostpanel` (порт 8080, автозапуск), запускает её и печатает
пароль администратора. Необычный порт/папка: `PANEL_PORT=9000 sudo bash install.sh`.

Пароль после установки: `cat /opt/hostpanel/admin.txt` (логин `admin`,
меняется в Настройках). Управление службой: `systemctl status|restart hostpanel`,
логи: `journalctl -u hostpanel -f`.

Удаление: `sudo bash uninstall.sh` (файлы сайтов и бэкапы не трогаются).

## Обновление прямо из панели

В «Настройках» есть карточка «Обновления панели»: кнопка «Проверить обновления»
сравнивает установленную версию с версией в репозитории на GitHub; если вышла
новая — кнопка «Обновить до vX.Y.Z» скачивает репозиторий, сохраняет копию
текущей панели в `/opt/hostpanel/panel.bak-<дата>`, заменяет файлы и
перезапускает службу автоматически. Данные и настройки (`/opt/hostpanel/`,
сайты, базы) не затрагиваются. Индикатор «⬆ доступна vX.Y.Z» также появляется
в подвале сайдбара. Данные сайтов не трогаются.

## Консольный клиент hcp

Вместе с панелью устанавливается CLI: `hcp` и команды-обёртки
`hcp-login`, `hcp-info`, `hcp-create`, `hcp-reset-password`, … (полный
список — `hcp-help`). Один раз выполните `hcp-login` (пароль вводится
скрыто; при включённой 2FA — ещё и код из приложения), дальше:

```bash
hcp-info                                 # сводка по серверу
hcp-create shop.ru --php 8.4 --db        # сайт + база
hcp-backup --all && hcp-backups          # резервная копия
hcp-reset-password                       # аварийный сброс пароля админа
hcp-logout                               # отозвать консольный доступ
```

Защита: команды работают только от root и только с самого сервера
(127.0.0.1) — даже украденный CLI-токен бесполезен из интернета; токен
256 бит хранится в `/opt/hostpanel/cli-token` (0600), в панели — только
его SHA-256; 8 неудачных `hcp-login` за 5 минут — пауза; каждая операция
попадает в журнал панели.

## Настройки ПО (пароли, параметры, конфиги)

Раздел «Система → Настройки ПО» появляется для всего установленного:
MariaDB (подключения, память, кодировка, медленные запросы, пароль root
по TCP), PostgreSQL, Redis (лимит памяти, вытеснение, requirepass),
Memcached (память/порт/адрес), Postfix (myhostname, размер письма),
Fail2ban (bantime/maxretry/ignoreip), phpMyAdmin (пароль входа и
config.inc.php), глобальные конфиги nginx и Apache, пулы PHP-FPM.
Перед каждым сохранением панель делает копию конфига в
`/opt/hostpanel/config-backups/<служба>/`, проверяет синтаксис
(nginx -t, apachectl configtest, postfix check, dovecot -n,
fail2ban-client -t, php -l) и откатывает изменения, если служба с новым
конфигом не поднимается.

## Структура проекта

```
hostpanel/
├── install.sh            # установка одной командой
├── uninstall.sh          # удаление
└── panel/                # Python-пакет (python3 -m panel)
    ├── __main__.py       # точка входа, CLI-аргументы
    ├── config.py         # константы: пути, лимиты, справочники
    ├── context.py        # глобальное состояние (режим, store, run())
    ├── state.py          # state.json, учётные данные, миграции
    ├── demo.py           # демо-наполнение (сайты, логи, живучесть)
    ├── utils.py          # чистые помощники (валидация, форматирование)
    ├── server.py         # HTTP-сервер, статика, CSRF, сессии
    ├── api/              # маршруты по доменам (61 маршрут)
    │   ├── router.py     # таблица маршрутов :id-параметры
    │   ├── auth.py       # PBKDF2, сессии, лимит попыток входа
    │   ├── general.py    # обзор, метрики /proc
    │   ├── sites.py      # сайты, поддомены, безопасность, конфиги
    │   ├── system.py     # PHP-модули, пакеты, службы, php.ini
    │   └── manage.py     # бэкапы, БД, cron, файрвол, файлы
    ├── core/             # системные интеграции
    │   ├── templates.py  # генерация nginx/apache/fpm + откат
    │   ├── security.py   # гео/IP/WAF/боты/rate-limit
    │   ├── confeditor.py # редакторы конфигов с валидацией
    │   ├── health.py     # живучесть: проверки, uptime, инциденты
    │   ├── stats.py      # статистика, фильтры логов, нагрузка
    │   ├── packages.py   # apt: модули PHP, обновления (в фоне)
    │   ├── backup.py     # tar.gz + mysqldump, zip-slip защита
    │   ├── files.py      # файловый менеджер
    │   ├── db.py         # MySQL/MariaDB
    │   ├── services.py   # systemd, cron, ufw
    │   ├── ssl.py        # certbot / openssl
    │   └── nodejs.py     # systemd-юниты Node.js
    ├── web/              # собранный фронтенд (Vue SPA): index.html + assets/
    └── core/panelupdate.py  # самообновление с GitHub
web-src/                  # исходники фронтенда (Vue 3 + Vite + vue-router)
    ├── src/              # views/ (разделы), components/ (кит), lib/, api/
    └── dist/             # сборка (npm run build) -> panel/web

Фронтенд — Vue 3 SPA с реальными URL (/sites/, /sites/<id>/, /databases/…,
history mode, без #решётки). Сборка: cd web-src && npm install &&
npm run build, затем скопировать dist в panel/web (или bash
build-production.sh — соберёт всё и упакует production/hostpanel-<версия>.tar.gz).
Сервер отдаёт index.html на любой «страничный» путь (SPA-fallback в
server.py) и /assets/* с долгим кешем (хеш в имени файла).
```

## Запуск без установки (демо)

```bash
python3 -m panel --demo --port 8080        # безопасный демо-режим
python3 -m panel --demo --home ./данные    # своя папка данных
sudo python3 -m panel --port 9000          # рабочий режим вручную
```

## Возможности

- **Установка ПО**: каталог служб в стиле ISPmanager — установка и удаление
  nginx / Apache / PHP 8.1–8.2 (PPA ondrej) / MariaDB / PostgreSQL / Redis /
  Memcached / certbot / fail2ban / Node.js / Composer / git прямо из панели,
  в фоне, с прогрессом и защитой используемых служб (не даст удалить
  nginx, на котором живут сайты).

- **Сайты**: nginx+PHP-FPM / nginx+Apache / Apache / nginx+Node.js / статика,
  выбор версии PHP и модулей, пулы FPM, Node-приложения (systemd, npm, журнал).
- **Поддомены**: кнопка «+» в строке сайта или из карточки; отдельный docroot
  (`subdomains/<имя>/public_html`), свой SSL и своя версия PHP.
- **Отключение сайта**: конфиг снимается с sites-enabled — сайт перестаёт
  отвечать, данные остаются. Отдельно — режим обслуживания (HTTP 503 + страница
  «ведутся работы»).
- **Фильтры в духе Cloudflare** (вкладка «Фильтры» у сайта): доступ по странам
  (гео-режимы «только эти» / «кроме», nginx GeoIP2), чёрный/белый списки IP,
  блокировка ботов и сканеров, базовый WAF (SQLi/XSS/скрытые файлы),
  ограничение запросов/сек с burst (защита от DDoS).
- **Редакторы конфигов**: nginx.conf, apache.conf, пул FPM и php.ini сайта
  прямо из карточки. Валидация перед применением (nginx -t, apachectl
  configtest, правила php.ini) и автоматический откат при ошибке.
- **PHP-модули и обновления**: установка phpX.Y-модулей из apt в фоне с живым
  логом, обновление индексов, выборочное обновление пакетов (PHP, веб-сервер,
  БД…), общий редактор php.ini с подсказками на русском.
- **Живучесть**: фоновые проверки каждого сайта (интервал настраивается),
  доступность за 24 ч и 7 дней, среднее время ответа, инциденты, уведомления
  о недоступности/восстановлении.
- **Нагрузка сайта на систему**: CPU/память PHP-воркеров пула и Node-процесса
  (ps), суммарная нагрузка всех сайтов на дашборде.
- **Логи с фильтрами**: поиск по тексту, код статуса, IP, подстрока URL,
  период по датам, «только ошибки 4xx/5xx», «только боты»; подсветка ошибок.
- **Бэкапы**: файлы сайтов + дампы MySQL + state, скачивание, восстановление
  (с защитой от zip-slip), хранение N копий, автобэкап по cron.
- **Файловый менеджер**: навигация, редактор, загрузка/скачивание, права,
  распаковка zip/tar.gz; в рабочем режиме корни ограничены
  (/var/www, /etc/…, папка панели) — снимается галочкой в настройках.
- Прочее: базы MySQL, службы systemd с перезапуском, планировщик cron,
  брандмауэр ufw, журнал аудита всех операций.

## Безопасность

- Пароль — PBKDF2-HMAC-SHA256 (200 000 итераций), сессии — HttpOnly cookie
  SameSite=Strict, все мутации требуют заголовок X-Panel-Token (CSRF),
  8 попыток входа за 5 минут с одного IP, аудит каждой операции.
- Внешние команды — списком аргументов без shell; имена доменов, IP, стран,
  портов, cron-выражений и путей валидируются; распаковка архивов защищена
  от zip-slip; файловый менеджер не выходит за разрешённые корни.
- Порт панели держите закрытым снаружи (ufw) или ходите по SSH-туннелю:
  `ssh -L 8080:127.0.0.1:8080 user@server`. Смените пароль после установки.

## Ограничения

- Рабочий режим рассчитан на Debian/Ubuntu с systemd; отсутствующие
  компоненты (certbot, mysql, ufw, geoip2) деградируют без падений.
- Гео-фильтры по странам требуют модуль nginx geoip2 и базы GeoLite2
  (панель подскажет команду установки).
- Почтовый сервер (ящики, приём/отправка писем) не входит в функциональность.
