# HostPanel — предложения по улучшению до продакшен-версии

Целевой пользователь: **веб-мастер-новичок**, который только что создал сайт и первый раз видит VPS.
Принципы: (1) безопасно по умолчанию, (2) ни одно действие без подсказки «что это и что будет», (3) типовые задачи WordPress-сайта — в 1–3 клика, (4) ошибки — человеческим языком с кнопкой «как исправить».

Приоритеты: 🔴 критично для продакшена · 🟡 сильно повышает качество · 🟢 приятно/конкурентно.

---

## A. Безопасность продакшена (база)

| Приоритет | Улучшение | Детали |
|---|---|---|
| 🔴 | **TLS для самой панели** | Сейчас панель — чистый HTTP на 0.0.0.0:8080, пароль и сессии ходят открытым текстом. Вариант: при установке выпускать Let's Encrypt на `panel.<домен>` и ставить nginx-фронт (443 → 127.0.0.1:8080) с автопродлением; панель продолжать слушать только 127.0.0.1. Дать в настройках переключатель «Доступ к панели: только локально / по домену с HTTPS» |
| 🔴 | **Установщик настраивает ufw сам** | install.sh должен включать ufw: разрешить 22/80/443, закрыть 8080/8081/3306/6379/11211 наружу. Сейчас на живом сервере ufw выключен и панель торчит в интернет |
| 🔴 | **fail2ban-jail для панели** | В `api/auth.py` лимит попыток живёт в памяти и только на IP. Добавить jail по логам панели (`/var/log/hostpanel/auth.log` — писать туда неудачные входы) + строку-подсказку в UI «включить защиту от перебора» |
| 🔴 | **CSP и отказ от localStorage** | `core.js` хранит session-токен в localStorage — любая XSS = полный доступ. Cookie HttpOnly уже есть — убрать дубль в localStorage; добавить `Content-Security-Policy: default-src 'self'` (панель статична, инлайн-скриптов нет) |
| 🟡 | **Ограничение терминала** | `/api/exec` — root-shell из браузера. Минимум: отдельное подтверждение паролем при включении (сейчас просто пункт меню), лог команд в audit, опция «выключить терминал» в настройках |
| 🟡 | **Хранить сессии переживаемо** | SESSIONS в памяти: рестарт панели = разлогин. Писать активные сессии в state (или отдельный файл) — новичок не должен думать, почему «вышло само» |
| 🟡 | **Очередь фоновых задач** | `packages._run_bg` — один глобальный флаг: пока ставится phpMyAdmin, нельзя обновить apt. Сделать очередь задач (id, статус, лог) — это же фундамент для «центра задач» UI |
| 🟢 | **Логирование auth в journald с структурой** | Единый формат строк для fail2ban: `ip=1.2.3.4 result=fail user=admin` |
| 🟢 | **Обновление самой панели** | Пункт «Проверить обновления» (сравнить версию с URL) + самособлюдаемая процедура обновления (скачать, заменить panel/, рестарт службы) |

## B. Мастер первого запуска и UX новичка

| Приоритет | Улучшение | Детали |
|---|---|---|
| 🔴 | **Welcome-мастер** | Первый вход (пока `must_change_password`) → пошаговый wizard: 1) сменить пароль + включить 2FA (QR прямо там) 2) «создать первый сайт» (домен → DNS-проверка → PHP/версия → база) 3) «выпустить SSL» (только после dns_ok) 4) «проверить сайт» (health-проверка). Сейчас эти шаги разбросаны по разделам |
| 🔴 | **DNS-подсказка при создании сайта** | Уже есть `/api/site/:sid/dns_check` — вывести его результат прямо в карточке сайта плашкой: «Домен ещё не указывает на сервер. Добавьте A-запись `A @ → 193.232.90.85` у регистратора. SSL выпускать только после этого». Это главная точка отчаяния новичка |
| 🟡 | **Режим «Простой/Эксперт»** | Переключатель: простой скрывает SQL-консоль, терминал, редакторы конфигов, FPM-пулы; эксперт показывает всё. В коде — один флаг в ME/settings |
| 🟡 | **Объяснители ошибок** | Центральный словарь типовых ошибок (nginx -t failed, DNS не сходится, DB connection refused, диск переполнен, порт занят) → человекочитаемое описание + кнопка «что делать». Сейчас тексты ошибок хорошие, но местами технические (`err: str(e)`) |
| 🟡 | **Чек-лист здоровья сайта** | В карточке сайта автоматический «аудит» по кнопке: HTTPS работает, HTTP→HTTPS редирект, gzip/brotli, кэш-заголовки, security headers, PHP версия EOL?, диск/логи не растут. Результат — список с галочками и ссылками «исправить» |
| 🟢 | **Подсказки-тултипы ко всем полям** | В FPM-пулах, php.ini (уже есть PHP_INI_RULES — переиспользовать стиль), настройках ПО: «что будет, если поставить слишком большое max_children на 2 ГБ RAM» |
| 🟢 | **Поиск по панели** | Один инпут: «домен», «почта», «php» → переходит в раздел. Новичок не знает, где что лежит |

## C. Функции «как у больших панелей»

| Приоритет | Улучшение | Детали |
|---|---|---|
| 🔴 | **Автопродление SSL + мониторинг срока** | Список сертификатов с датами истечения на дашборде; cron-задача панели: `certbot renew` + reload + уведомление при <14 дней. Сейчас expiry пишется в state, но никто его не проверяет |
| 🔴 | **WordPress в 1 клик** | Целевая аудитория = WP. Кнопка «Приложение» при создании сайта: wp-cli (скачать ядро, wp-config с данными базы из панели, права, salt-ключи) + галочки «ru-язык», «префикс таблиц». Установленный WP → пункт «Обновить ядро/плагины» через wp-cli |
| 🟡 | **Nginx-профили производительности** | Галочки в карточке сайта: gzip/brotli, статика с expires 30d, HTTP/2, security headers (HSTS, X-Frame), кэш страницы (fastcgi_cache с зоной на домен + очистка). Одна галочка = пересборка конфига с валидацией (механизм уже есть) |
| 🟡 | **HTTP→HTTPS редирект и HSTS** | После выпуска LE — автоматом `return 301 https://…` в конфиге (сейчас оба listen живут параллельно, новичок не заметит, что сайт доступен и по http) |
| 🟡 | **Ротация логов сайтов** | Логи растут в /var/log/hostpanel без ротации — добавить logrotate-конфиг при установке (daily, 14, compress) и показывать «размер логов» с кнопкой «очистить» (частично уже есть log_size в API) |
| 🟡 | **Рекомендации лимитов FPM** | Кнопка «подобрать под сервер»: расчёт max_children из доступной RAM и среднего веса воркера (данные site_load уже собираются) |
| 🟢 | **Staging-копия сайта** | Кнопка «создать копию» → поддомен staging.<домен> с копией файлов+базы, отдельный robots noindex; «развернуть staging → прод» |
| 🟢 | **Git-деплой** | Поле «репозиторий» у сайта: webhook/кнопка «pull», запись в журнал. Git уже в каталоге ПО |
| 🟢 | **Webhook/канал уведомлений** | К SMTP/TG добавить универсальный webhook (JSON POST) — интеграция с чем угодно; события уже сгруппированы в notify.send |
| 🟢 | **Еженедельный отчёт** | Cron-дайджест: аптайм сайтов, использованный диск, обновления, ошибки 5xx за неделю — письмом. Весь материал уже собирается (health, stats, packages) |
| 🟢 | **Мониторинг снаружи** | Проверка сайтов через внешний зонд (опционально) — health-поток проверяет с самого сервера и не увидит падение сети сервера |

## D. Технический долг

| Приоритет | Улучшение | Детали |
|---|---|---|
| 🟡 | **Удалить мёртвый код** | `panel/general.py` (дубль api/general.py), синхронизировать `VERSION` с `config.py`, обновить README под 2.7 |
| 🟡 | **Тесты** | Хотя бы smoke-тесты на демо-режиме: `python3 -m panel --demo` + прогон всех GET-маршрутов + контрольные генерации конфигов (templates.py — чистая функция строк, легко тестируется). Регрессия типа fail2ban-конфига ловится тестом «сохрани настройки каждой службы в демо → конфиг валиден для своего парсера» |
| 🟡 | **Валидация конфигов по типу файла** | Урок fail2ban: `_cfg_set` не знает синтаксис файла (пробел vs `=`). Передавать в `_apply_files` уже есть `kind`-валидаторы — применять их и в `save_fields`, а не только в редакторе файла |
| 🟢 | **Ограничение частоты на всё API** | Простой token-bucket на IP для мутаций (сейчас лимит только на вход) |
| 🟢 | **Структурированные логи панели** | JSON-строки в journald (`-o cat`) — упростит будущую аналитику и fail2ban |
| 🟢 | **Разделение прав** | Долгосрочно: операции сайтов — от выделенного юзера через sudo-белый список, root — только для системных действий. Пока панель и так root, но это сузит последствия бага |

## E. Что уже хорошо (не трогать)

- Единая точка `run()` без shell → нет инъекций через домены/пути.
- Валидация+откат на каждом изменении конфига (nginx -t, configtest, php-fpm -t, php -l).
- Zip-slip-защита в файлах/бэкапах/распаковке.
- CSRF + HttpOnly + SameSite=Strict + лимиты входа + 2FA + CLI только с localhost.
- Аудит всех операций и понятные русские сообщения об ошибках.
- Предпроверки перед созданием сайта («не установлено: PHP 8.3 — откройте Установка ПО»).

## F. Второй раунд предложений — удобство (2026-11-03, v2.12.0+)

Без git-деплоя, staging и WordPress-инструментов.

| # | Функция | Что даёт новичку | Трудоёмкость |
|---|---|---|---|
| 1 | **Диагностика домена в 1 клик** | Кнопка в карточке сайта: A/AAAA/MX/TXT/NS-записи, SPF, пропагация DNS по серверам, ответ «что должно быть» vs «что есть». Главная боль новичка — DNS | Низкая |
| 2 | **SPF/DKIM/DMARC-мастер почты** | Показ готовых DNS-записей для копирования, генерация DKIM-ключей (opendkim), проверка попадания писем в спам. Свой почтовый сервер без этого не живёт | Средняя |
| 3 | **Кнопка «Куда уходит диск»** | Top-10 каталогов по размеру (логи, бэкапы, tmp, кэш, папки сайтов) + кнопки очистки. Диск на 15 ГБ кончается быстро | Низкая |
| 4 | **Ротация логов сайтов** | logrotate-конфиг при установке + счётчик размера и кнопка «очистить» прямо в просмотре логов. Логи nginx+php растут гигабайтами | Низкая |
| 5 | **Импорт сайта архивом** | Мастер «переезд с другого хостинга»: загрузить zip файлов + дамп базы → распаковка в docroot + импорт + проверка. Всё по частям уже есть — собрать в один флоу | Средняя |
| 6 | **Еженедельный отчёт** | Письмо/TG: аптайм сайтов, ошибки 5xx, свободное место, доступные обновления, последние операции. Данные уже собираются | Низкая |
| 7 | **Уведомления о безопасности** | В TG: вход в панель (IP + страна + устройство), баны fail2ban, неудачные попытки входа — не тонут в общем журнале | Низкая |
| 8 | **Подбор лимитов FPM кнопкой** | «Подобрать под сервер»: расчёт max_children из свободной RAM и среднего веса воркера (site_load уже собирается) + предупреждение при риске OOM | Низкая |
| 9 | **Библиотека nginx-сниппетов** | Кнопки-шаблоны в карточке сайта: redirect www→non-www, закрыть /admin по IP, свой client_max_body_size, отдача статики с другого домена. Каждая — галочка с валидацией как perf-профили | Средняя |
| 10 | **Центр задач с историей** | Очередь уже есть; добавить журнал последних задач (установка ПО, бэкапы, SSL) с результатами и временем — «а что происходило, пока меня не было» | Низкая |
| 11 | **Поиск по панели** | Один инпут в сайдбаре: домен, база, ящик, раздел, настройка → переход. Новичок не помнит, где что лежит | Средняя |
| 12 | **Публичный /status для мониторингов** | Опционально включаемый JSON-эндпоинт: аптайм, версия, состояние служб — для UptimeRobot/BetterStack без доступа в панель | Низкая |
| 13 | **Проверка сайта извне** | Health-проверка с самого сервера не увидит падение сети сервера; опция: параллельный пинг через внешний webhook (UptimeRobot API) с выводом обоих мнений в «Живучести» | Средняя |
| 14 | **Мобильная адаптация UI** | Проверить и дожать: таблицы в карточки, крупные тач-цели. Владельцы сайтов часто глядят панель с телефона | Средняя |
| 15 | **Редактор файлов: поиск/замена + список файлов сайта в карточке** | Мелочи, экономящие кучу кликов: Ctrl+F в редакторе кода, кнопка «файлы этого сайта» уже есть, добавить «свежие изменённые файлы» | Низкая |

Рекомендуемый порядок: 1 → 4 → 3 → 6 → 7 → 10 (быстрые победы), затем 2, 5, 9.
